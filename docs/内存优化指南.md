# TwinBrain 内存优化指南

本指南提供 CUDA 内存优化策略，帮助在有限的 GPU 资源上训练大型模型。

## 概述

TwinBrain 使用异构图神经网络处理多模态脑成像数据，可能消耗大量 GPU 内存。本指南提供实用的优化技术。

## 内存使用分析

### 典型内存消耗

```
总 GPU 内存需求 = 模型参数 + 激活值 + 梯度 + 优化器状态 + 数据批次

示例（Schaefer200, 批次大小=32）：
- 模型参数：~500MB
- 激活值：~1-2GB（取决于深度）
- 梯度：~500MB
- 优化器（Adam）：~1GB
- 数据批次：~500MB
- 缓冲区：~500MB
总计：~4-5GB
```

### 内存瓶颈

1. **大批次大小**：线性增加内存
2. **深层网络**：激活值累积
3. **长序列**：时序数据占用
4. **多模态**：fMRI + EEG + DTI 同时加载

## 优化策略

### 1. 调整批次大小

**最简单有效的方法**：

```yaml
# config.yaml
training:
  batch_size: 16  # 从 32 减小到 16
  
  # 使用梯度累积保持有效批次大小
  gradient_accumulation_steps: 2  # 有效批次 = 16 * 2 = 32
```

**代码实现**：
```python
accumulation_steps = 2
optimizer.zero_grad()

for i, batch in enumerate(dataloader):
    loss = model(batch) / accumulation_steps
    loss.backward()
    
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

**内存节省**：~30-50%

### 2. 混合精度训练

使用 FP16 代替 FP32：

```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()

for batch in dataloader:
    optimizer.zero_grad()
    
    # 在 FP16 下前向传播
    with autocast():
        loss = model(batch)
    
    # 缩放损失并反向传播
    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()
```

**配置启用**：
```yaml
training:
  use_amp: true  # 自动混合精度
```

**内存节省**：~40%
**速度提升**：~1.5-2x

### 3. 梯度检查点

对于深层网络，重新计算而不是存储激活值：

```python
from torch.utils.checkpoint import checkpoint

class DeepGNN(nn.Module):
    def forward(self, x):
        # 使用检查点的层
        x = checkpoint(self.layer1, x)
        x = checkpoint(self.layer2, x)
        x = self.layer3(x)  # 最后一层不检查点
        return x
```

**权衡**：
- 内存节省：~40-60%
- 速度影响：~20% 较慢（重新计算）

### 4. 优化数据加载

**问题**：一次性加载所有数据到 GPU

**解决方案**：
```python
class LazyDataLoader:
    """延迟加载数据到 GPU"""
    
    def __init__(self, data_list):
        self.data_list = data_list
        # 数据保持在 CPU
    
    def __getitem__(self, idx):
        # 只在需要时加载到 GPU
        return self.data_list[idx].to('cuda')
```

**配置**：
```yaml
data_loading:
  pin_memory: true       # 加速 CPU->GPU 传输
  num_workers: 4         # 并行加载
  prefetch_factor: 2     # 预取批次
```

### 5. 模型剪枝

减小模型大小：

```yaml
model:
  # 减少隐藏维度
  hidden_dim: 128  # 从 256 减小
  
  # 减少层数
  num_layers: 2    # 从 3 减小
  
  # 减少注意力头数
  num_heads: 4     # 从 8 减小
```

**内存节省**：~30-70%（取决于减少程度）

### 6. 清理 GPU 缓存

定期清理未使用的内存：

```python
import torch

# 训练循环中
if epoch % 10 == 0:
    torch.cuda.empty_cache()
    
# 评估后
model.eval()
with torch.no_grad():
    evaluate(model, val_data)
torch.cuda.empty_cache()
```

### 7. 使用 CPU offload

对于超大模型，将部分参数放在 CPU：

```python
from torch.nn.parallel import DistributedDataParallel as DDP

# 简单的 CPU offload
class HybridModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.gpu_layers = nn.Sequential(...).to('cuda')
        self.cpu_layers = nn.Sequential(...).to('cpu')
    
    def forward(self, x):
        x = self.gpu_layers(x)
        x = x.to('cpu')
        x = self.cpu_layers(x)
        return x.to('cuda')
```

### 8. 序列截断

对于长时序数据：

```yaml
data:
  max_sequence_length: 100  # 限制序列长度
  sequence_stride: 10       # 使用滑动窗口
```

```python
def truncate_sequence(data, max_len=100):
    """截断长序列"""
    if data.shape[1] > max_len:
        # 只保留前 max_len 个时间点
        data = data[:, :max_len, :]
    return data
```

### 2. PyTorch 内存分析器

```python
import torch

# 开始记录
torch.cuda.memory._record_memory_history()

# 生成报告
```

查看报告：
```python
import pickle
import matplotlib.pyplot as plt

    snapshot = pickle.load(f)

    print(f"{entry['name']}: {entry['size']/1e6:.2f}MB")
```

### 3. 内存检查代码

```python
def print_gpu_memory():
    """打印 GPU 内存使用"""
    if torch.cuda.is_available():
        allocated = torch.cuda.memory_allocated() / 1e9
        reserved = torch.cuda.memory_reserved() / 1e9
        print(f"GPU Memory: {allocated:.2f}GB allocated, {reserved:.2f}GB reserved")

# 在训练循环中使用
for epoch in range(num_epochs):
    print_gpu_memory()
    train_epoch(model, data)
    print_gpu_memory()
```

## 故障排除

### 问题：CUDA out of memory

**立即尝试**：
1. 减小批次大小：`batch_size: 8`
2. 启用混合精度：`use_amp: true`
3. 清理缓存：`torch.cuda.empty_cache()`

**如果仍然失败**：
4. 减小模型：`hidden_dim: 64`
5. 使用梯度检查点
6. 截断序列长度

### 问题：内存泄漏

**症状**：内存持续增长

**检查**：
```python
# 确保使用 no_grad 进行评估
with torch.no_grad():
    evaluate(model, val_data)

# 不要在循环中累积张量
# 错误：
losses = []
for batch in dataloader:
    loss = model(batch)
    losses.append(loss)  # 保留计算图！

# 正确：
losses = []
for batch in dataloader:
    loss = model(batch)
    losses.append(loss.item())  # 只保存数值
```

### 问题：内存碎片化

**症状**：有可用内存但分配失败

**解决**：
```python
# 定期整理内存
if epoch % 5 == 0:
    torch.cuda.empty_cache()
    torch.cuda.synchronize()
```

## 性能权衡

| 技术 | 内存节省 | 速度影响 | 精度影响 |
|------|----------|----------|----------|
| 减小批次 | 30-50% | +0% | 无 |
| 混合精度 | 40% | -30% (更快) | 可忽略 |
| 梯度检查点 | 40-60% | +20% | 无 |
| 模型剪枝 | 30-70% | -20% (更快) | 可能轻微 |
| 序列截断 | 20-40% | -10% (更快) | 取决于任务 |

## 最佳实践

1. **从小开始**：先用小配置验证代码
2. **逐步增加**：逐渐增大批次/模型大小
3. **持续监控**：使用 nvidia-smi 监控
4. **定期清理**：每个 epoch 清理缓存
5. **混合精度优先**：最简单的优化
6. **梯度累积**：保持有效批次大小
